================================================================================
  SIF SENTINEL AI — DEFINITIVE FEATURE & PAGE REFERENCE GUIDE
  (Sourced directly from frontend source code)
================================================================================

This document is a definitive, code-accurate explanation of every page and
every feature in the SIF Sentinel AI frontend. It is intended as a complete
reference for team members, judges, and evaluators to understand exactly what
each screen does, how it works technically, and what value it provides.

The platform turns unstructured incident narrative text into structured,
scored, explainable, and actionable safety intelligence — end-to-end.

CORPUS SIZE: 16,249 total records (4,813 incidents + 11,436 fatalities)
MODEL VERSION: sif-sentinel-v1.0-tfidf-xgb
FRONTEND FRAMEWORK: React 18 + Vite + Tailwind CSS 3
API: FastAPI backend at http://localhost:8000/api/v1

================================================================================
  GLOBAL FEATURES (PRESENT ACROSS ALL PAGES)
================================================================================

THEME SYSTEM (Light / Dark Mode):
  - Toggleable dark/light theme using a .dark class on the HTML root.
  - Persisted to localStorage and reads system preference on first visit.
  - All colors use CSS custom properties (--color-bg, --color-surface, etc.)
    with space-separated RGB values enabling Tailwind alpha modifiers.
  - Transitions: background-color and color animate at 250ms on every change.
  - Toggle button: Sun icon (in dark mode) or Moon icon (in light mode).
  - Location: Topbar on all interior pages; custom button on the Landing page.

LOADING STATES (Skeleton Screens):
  - Every async data section has its own SkeletonBlock / SkeletonCard /
    SkeletonChart / SkeletonTable component that mimics the layout of the
    content it replaces, preventing layout shift.
  - Skeletons use a shimmer animation (200% wide gradient sliding left to right).

ERROR STATES:
  - React Error Boundaries (SectionErrorBoundary) isolate sections so a
    failure in one panel (e.g., Safety Memory) does not crash the whole page.
  - Errors display a descriptive message with a "Retry" button that re-fires
    the API call.

SYNTHETIC DATA DISCLOSURE:
  - All site/area/department metadata is synthetically generated (OSHA source
    data contains no location fields). This is disclosed on screen via a
    SyntheticBadge component that appears next to any synthetic field.
  - The badge is visible on: Executive Dashboard site table, Incident Explorer
    cards, Incident Detail header, and Safety Memory pattern cards.

NAVIGATION (Sidebar):
  - 12 navigation links, grouped by category.
  - Active link has a left-side 2px brand-colored inset shadow + gradient
    background highlight in dark mode.
  - All icons from lucide-react.

ACCESSIBILITY:
  - .skip-link: "Skip to content" keyboard shortcut (visible on focus).
  - All interactive elements have unique IDs and ARIA roles.
  - Copilot tab controls use arrow-key navigation (aria-selected, role="tab").
  - All animations respect prefers-reduced-motion: Intersection Observer-based
    reveals fall through immediately; all CSS transitions set to 0.001ms.

3. % High-or-above: Percentage of reports in HIGH or CRITICAL band.

4. Avg SIF Probability: Mean P(SIF) across all records as a percentage.

- Components: CartesianGrid, XAxis, YAxis, Tooltip, Area, and two Lines.
- Blue solid Line: Historical incident counts ("History").
- Red dashed Line: Forecast expected values ("Forecast").
- Blue gradient Area: Confidence range band [lower, upper] around the forecast.
- Category selector dropdown: If multiple hazard categories exist, the user
  can switch between them (e.g., WORK_AT_HEIGHT, CONFINED_SPACE, etc.).
- Trend label: "WORK_AT_HEIGHT is trending up (+12.3% vs mean)" — shown
  below the chart in matching red text.
- Synthetic timeline badge: Shown in the chart header if forecast data
  has is_synthetic_timeline=true.

---- LSR VIOLATION DONUT CHART ----
- Fills the remaining 1/3 of the grid.
- A PieChart (Recharts) showing the top 6 Life Saving Rule violations as a
  donut, with each rule assigned a distinct series color.
- Center label: Total violation count.
- Legend below: Rule name (human-readable, underscores replaced) + count.

---- SITE RISK RANKING TABLE ----
- Sortable table spanning full width.
- Columns: Site, Reports, Critical, High, Avg SIF Prob, Composite Index.
- Each site name is a clickable link that applies a site filter in Zustand's
  filterStore and navigates to /incidents (so the user gets a pre-filtered view).
- The Composite Index is shown alongside a RiskBadge (color-coded band).
- Synthetic data badge shown next to each site that uses synthetic org fields.

---- HEADER ----

---- FORM ----
- Narrative Textarea (required):
  * 6-row resizable textarea.
  * Placeholder: "Describe what happened. Be specific about hazards, equipment,
    and conditions (e.g., 'Worker was adjusting a conveyor belt...')"
  * Minimum validation: non-empty.
- Optional Metadata Grid (3 dropdowns, side by side on md+ screens):
  * Site Location: 9 options + "Auto-Detect by AI" (empty value = let backend
    infer from narrative keywords using synth_site_area()).
  * Operational Area: 5 options (RIG, REFINERY, PIPELINE, WAREHOUSE, WORKSHOP)
    + "Auto-Detect by AI".
  * Department: 7 options + "Auto-Detect by AI".
- Auto-Detect explanation panel: Informs user that leaving dropdowns at
  "Auto-Detect" triggers the backend's deterministic classification.
- Error display: A red bordered alert box with AlertTriangle icon and message.
- Submit button: Shows "Analyzing..." with a spinning Loader2 icon while
  the API call is in flight (isPending state).
- Cancel button: Navigates back to /incidents.

---- WHAT HAPPENS ON SUBMIT ----
1. POST /api/v1/incidents with { narrative, site?, area?, department? }.
2. The backend InferenceEngine runs the full pipeline (NER → SIF score →
   LSR tags → vector search → risk fusion → fatality twin → CAPA → memory recall).
3. Response includes the full analysis JSON with a report_id.
4. Frontend auto-navigates to /incidents/:id to show the full analysis.

================================================================================
  PAGE 5: INCIDENT DETAIL (/incidents/:id)
================================================================================

Route: /incidents/:id (works for both INC- and FAT- prefixed IDs)
API calls: GET /api/v1/incidents/:id, GET /api/v1/incidents/:id/memory
Layout: Two-column on xl screens (main analysis left, sticky Copilot sidebar right)

---- HEADER CARD ----
- Report ID (monospace) + "Synthetic org fields" badge.
- Full narrative text (unstyled prose).
- Chips: Site, Area, Department, Activity.
- Date reported.
- Model version + input hash (SHA-256 prefix of the narrative, proves
  exactly which text was scored).
- RiskGauge component (circular gauge showing P(SIF) as a number,
  band colour around the arc, confidence score below).
- Fact tiles at the bottom of the header:
  * Barrier Failure: Yes (red) / No (green)
  * Root Cause: PROCEDURE_VIOLATION / EQUIPMENT_FAILURE / HUMAN_ERROR

---- "WHY THIS SCORE" SECTION ----
Two complementary panels explaining the AI's reasoning:

Panel 1 — Risk Fusion Bar (RiskFusionBar component):
  Shows the 4 weighted components that make up the final risk score:
  - P(SIF) Text + Structured (55%): The blended probability from the
    logistic regression + XGBoost classifier.
  - LSR Severity (25%): max(LSR_confidence × severity_weight) across
    all tagged rules.
  - Barrier Failure (10%): 1.0 if a barrier failure was detected, else 0.0.
  - Fatality Precedent (10%): Max cosine similarity score against fatal cases.
  Each component has a colored bar scaled to its contribution to the final score.

Panel 2 — Token Attribution (ExplanationPanel component):
  Shows the specific words (TF-IDF tokens) from the narrative that most
  influenced the logistic regression score, with their weights. For a LR model,
  contribution_j = coefficient_j × tfidf_value_j is the exact (not approximate)
  attribution — equivalent to what SHAP converges to on linear models.
  Example output: "energized: +0.82", "lockout: +0.71", "verified: -0.45"

---- LSR MAPPING SECTION ----
- LsrMapping component.
- Shows each triggered Life Saving Rule with:
  * Rule name (human readable)
  * Confidence percentage bar
  * Only shown if confidence ≥ 20% (LSR_CONFIDENCE_FLOOR).
- Rules with confidence ≥ 80% highlighted in red.
- "No LSR violations detected" shown if no rules triggered.

---- EXTRACTED ENTITIES SECTION ----
- EntityTags component.
- Four categories, each with colour-coded chips:
  * Hazards (orange): e.g., "energized cable", "arc flash"
  * Equipment (blue): e.g., "junction box", "circuit breaker"
  * Activities (green): e.g., "electrical maintenance", "lockout tagout"
  * Conditions (red): e.g., "isolation not verified", "guard removed"
- Empty category = greyed-out "None detected" label.

---- FATALITY TWIN — ESCALATION CHAIN ----
- FatalityTwinChain component.
- Displays a visual left-to-right flowchart of the chain:
  [Contact Type] → [Barrier Status] → [Outcome] → [Fatality]
- Chain nodes derived from matched fatal cases, not freely generated.
- Contact type (e.g., "Electrical contact"): matched from report text.
- Barrier node: "Barrier failure: Lock-out/isolation not verified" (only shown
  if barrier_failure flag is True; never asserted if it wasn't in the text).
- Outcome: Majority-voted injury type from matched fatalities.
- Statistics: "Matched X fatal cases, max similarity Y%, avg likelihood Z%"
- Matched fatal report IDs listed below the chain.

---- SAFETY MEMORY SECTION ----
- SafetyMemoryPanel component (same as used on /memory page).
- Shows the memory recall for this specific report ID.
- Verdict + matched cases + common cause + recommended action.
- Has its own independent AsyncSection error boundary — a crash here
  does not affect the rest of the analysis page.

---- MATCHED FATAL CASES ----
- Clickable list of up to 10 historically matched fatality records
  (from similar_fatalities array), each showing:
  * Fatality report ID (monospace)
  * Narrative snippet (truncated to 140 chars)
  * Similarity percentage (cosine similarity × 100)
- Clicking navigates to /incidents/FAT-XXXX for that fatality record.

---- RECOMMENDED CAPA ----
- CapaPanel component.
- Corrective Actions (C1/C2 priority): Immediate, rule-specific actions.
- Preventive Actions (P1/P2 priority): Systemic safety improvements.
- Training Needs: Specific refresher training topics.
- Toolbox Talk: 5-minute team briefing script with 4 bullet points,
  tailored to the exact hazards and equipment in the narrative.
- Precedent note: Lists matched fatal case IDs that motivate the actions
  (or "No closely matching fatal precedent" if none).

---- SAFETY COPILOT SIDEBAR ----
- On xl screens: Sticky right-side column (360px wide) with a full-height
  CopilotChat in compact mode. Stays visible while scrolling the analysis.
- On smaller screens: Shown as an inline card at the bottom of the page.
- "Ask the Copilot about this report" — pre-loaded with the current report
  context for focused Q&A.

  PAGE 6: SAFETY MEMORY (/memory)
================================================================================

Route: /memory
API calls: POST /api/v1/memory/recall, GET /api/v1/memory/patterns,
           GET /api/v1/memory/patterns/:id

---- RECALL BOX (TOP SECTION) ----
- Premium card with BrainCircuit icon and animated glowing orb.
- Description: "Paste the narrative you are about to report. Every one of
  the 16k historical records is checked before it is filed..."
- 4-row resizable textarea with placeholder example.
- Minimum length validation: 10 characters.
- "Use an example narrative" button pre-fills: "Worker touched energized
  cable while replacing a junction box; isolation was assumed but never
  physically verified."
- "Check safety memory" button: POSTs to /api/v1/memory/recall with top_k=8.
- Match count displayed after recall: "N match(es) returned" in a chip badge.
- Error state: Shows with retry button.

---- RECALL RESULTS (SafetyMemoryPanel component) ----
Verdict (color-coded):
  - NO_PRECEDENT: No similar historical event found.
  - WEAK_PRECEDENT: Low-similarity matches only.
  - REPEAT_PATTERN: Non-fatal repeated pattern.
  - RELATED_FATAL_PRECEDENT: Similar events, at least one was fatal.
  - REPEAT_FATAL_PATTERN: Direct match to fatal cases (highest alert).

Matched Cases list:
  - Up to 8 records (top_k=8), each showing similarity %, report ID, snippet.
  - source_type badge: "INCIDENT" (blue) or "FATALITY" (red).

Common Cause:
  - The majority-voted LSR rule across all matched cases.
  - Displayed as "X of Y matched cases — [rule name]".

Recommended Action:
  - The rule-specific corrective action from the recommendations module.

---- RECURRING PATTERNS (BOTTOM SECTION) ----
- Section header explains: "Reports that keep happening as the same event,
  ranked most-severe first."
- Stats: "N patterns over 16,249 reports" + "Derived clusters" badge.
- Deep-link support: Pattern cards are scroll-targeted when accessed via
  URL parameter ?pattern=<id>.
- Up to 20 pattern cards (PATTERN_LIMIT=20), each via PatternCard component:

PatternCard Component Details:
  - Pattern rank number (1, 2, 3...).
  - Representative narrative (the centroid-nearest narrative for that cluster).
  - Severity distribution bar: Fatal count scaled relative to max across all patterns.
  - Top terms: Most frequent n-gram tokens in that cluster.
  - Cluster size (number of incidents in this cluster).
  - Severity badge: Only shown if the cluster's severity profile deviates
    from the corpus baseline (e.g., unusually high non-fatal count).
  - Click to expand: Shows more detail including site distribution.

  PAGE 7: AI SAFETY COPILOT (/copilot)

Route: /copilot
Layout: Narrow (max-w-3xl) for Chat tab; Wide (max-w-6xl) for Structured tab.
API calls: POST /api/v1/copilot/query, POST /api/v1/copilot/structured-query

---- TAB SWITCHER ----
- Keyboard-accessible tab list (role="tablist", arrow key navigation).
- Two tabs: "Chat" (MessageSquareText icon) and "Structured query" (Filter icon).
- Active tab: Brand-600 background with white text and a glow shadow.
- Tab switch never discards conversation — CopilotChat is always mounted.

---- TAB 1: CHAT (CopilotChat component) ----
Message history (scrollable, newest at bottom):
  - User messages: Right-aligned, brand-600 background, rounded-br-sm tail.
  - AI messages: Left-aligned, surface background with border.
  
AI response anatomy:
  - Intent tag chip: Shows what the system understood (e.g., "SITE_RANKING",
    "MEMORY_RECALL", "STRUCTURED", "REPORT_LOOKUP").
  - Grounded indicator: Green "Grounded" chip if real report IDs back the answer;
    Red "Not grounded" chip if the system couldn't find supporting data.
  - Answer text: The prose response.
  - Citation chips: Monospace report ID badges (INC-XXXXXX, FAT-XXXXXX) that
    are clickable links navigating to /incidents/:id.

Example queries the system handles:
  - "What are the top safety risks?" → SUMMARY intent.
  - "Which is the most dangerous site?" → SITE_RANKING intent.
  - "Has someone been electrocuted by a junction box before?" → MEMORY_RECALL.
  - "Show CRITICAL incidents from Refinery Block A last week" → STRUCTURED.
  - "Tell me about report INC-220891725" → REPORT_LOOKUP.
  - "What CAPA actions for Rig-07?" → CAPA intent.

---- TAB 2: STRUCTURED QUERY (StructuredQueryPanel component) ----
Input:
  - A full-width text area for typing a multi-constraint query.
  - Example queries shown as clickable chip examples:
    * "Confined space incidents during monsoon with SIF > 80"
    * "Show CRITICAL incidents at Rig-07 where LOTO was bypassed"
  - "Run query" button.

Results display (StructuredResultView component):
  - "Recognised constraints" section: Shows each parsed filter as a green
    chip (e.g., "topic: confined space", "season: Jun–Sep", "SIF ≥ 0.80").
  - "Unrecognised terms" section (if any): Terms the parser couldn't map,
    shown in amber, so the user knows nothing was silently dropped.
  - Aggregate answer: "N reports match all X filters." with breakdown stats
    (most common site, most common LSR rule).
  - Zero-result relaxation: If 0 results, shows: "0 match all 4 constraints.
    Dropping [constraint] alone returns N matches." — tells user exactly
    which filter is binding.
  - Result table: List of matching report IDs with risk band badges and
    SIF probability percentages, all clickable.
  - Citation chips at the bottom.

  PAGE 11: LSR DASHBOARD (/lsr)

---- RULE VIOLATION RANKING CHART ----
- Horizontal BarChart (Recharts) with rules on the Y-axis.
- All bars use the same critical (red) color but varying opacity:
  opacity = 0.40 + 0.60 × (rule_count / max_count)
  This means the highest-violation rule has full opacity (critical red) and
  lower rules are lighter — never misread as a different risk band.

---- RULES TABLE WITH DRILL-THROUGH ----
- Expandable list, one row per Life Saving Rule.
- Each row shows: violation count, average SIF score, risk band badge.
- Expanding a rule triggers a "Drill through via semantic search":
  * Fires POST /api/v1/search/semantic with the rule name as the query.
  * Returns the top 5 semantically nearest incidents.
  * Each result is a clickable link to /incidents/:id.

---- DEPARTMENT RISK OVERVIEW ----
- Static table showing each department's report count, critical count,
  and composite risk index (sorted highest first).

  PAGE 13: KNOWLEDGE GRAPH (/graph)
================================================================================

Route: /graph
API calls: GET /api/v1/graph?limit=<N>
Library: Cytoscape.js via react-cytoscapejs

---- HEADER ----
- "Safety Knowledge Graph" with Waypoints icon.
- Description: "Ringed nodes have the highest barrier betweenness centrality —
  fixing that control would break the most incident pathways."
- Node limit selector: 50 / 100 / 150 / 300 nodes. Changing re-fetches graph.
- Color-coded legend: 9 node types (site, area, activity, hazard, barrier,
  root_cause, outcome, department, report) with matching dot colors.

---- CYTOSCAPE GRAPH CANVAS ----
Layout algorithm: COSE (force-directed, physics simulation).
  - nodeRepulsion: 14,000 (spread nodes apart)
  - idealEdgeLength: 80px
  - nodeOverlap: 24
